SupportHub Group 12 - Instructor feedback - 03 Vercel <-> Floci communication
==========================================================================
Date (UTC) 2026-11-26 ; isolated verification ; nothing deployed.

HOW THE PUBLIC VERCEL APIS REACH FLOCI (proposed, application side verified)
  Vercel function --HTTPS--> Cloudflare edge (Access app floci.<domain>, Service Auth policy:
  CF-Access-Client-Id / CF-Access-Client-Secret) --Cloudflare Tunnel (outbound from the VM)-->
  cloudflared container --http--> floci:4566 on the VM's private Docker network.
  No inbound port on the VM; Floci never published; unauthenticated requests stop at Cloudflare.
  The SDK still signs every request with the component IAM key; Floci enforces the IAM policy.

DIRECT AWS SDK PATHS (API -> Floci, need the tunnel)
  Source            Destination         Operation (IAM principal)                            Function
  Article API       S3 article-backups  PutObject/GetObject articles/* (supporthub-article-service)  version backup export/restore
  Search API        DynamoDB counters   UpdateItem/Scan (search-analytics-service)            live counters
  Search API        S3 analytics-exports PutObject/GetObject/List exports/*                   CSV export
  Search API        CloudWatch          PutMetricData SupportHub/Search                       metrics
  Identity API      SNS security-alerts Publish (supporthub-identity-service)                 security alerts
  (Secrets Manager from Vercel: optional - Vercel uses environment variables.)
INDIRECT PATHS (no Vercel -> Floci call; PostgreSQL outbox + ECS workers on the VM)
  Article API -> Neon article_event_outbox -> article-outbox-worker -> SQS -> editorial-article-consumer -> Neon
  Editorial API -> Neon editorial_publication_event_outbox -> publication worker -> SNS -> Lambda -> Neon receipts
  Editorial API -> Article/Search APIs: HMAC-signed HTTPS (no Floci involved)
  Consumer (ECS on the VM) -> Article API on Vercel: HMAC-signed HTTPS GET /internal/articles/:id
