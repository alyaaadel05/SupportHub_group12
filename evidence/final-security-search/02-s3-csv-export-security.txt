C. VERCEL DEPLOYMENT vs LOCAL EXPORT - DEFECT FOUND AND FIXED
==========================================================================
  Why the deployed Vercel Search & Analytics app cannot export:
    services/search-analytics-service/services/awsClients.js points the SDK at AWS_ENDPOINT_URL.
    Locally that is Floci (http://floci:4566 / localhost). Floci runs only on this PC (now meant to be
    loopback-only); Vercel's serverless functions run on the public internet and cannot reach it, and
    no real AWS S3 bucket exists (by design: no real AWS). If S3_EXPORT_BUCKET is unset on Vercel the
    code already answers 503 "Analytics export not configured" (consistent with the earlier production
    note "S3 analytics export not configured"). If it is set with an unreachable endpoint, the request
    hung in SDK retries. Making the Vercel export work requires a public/real S3 endpoint, a tunnel or
    an architecture change - NOT done (needs your approval).
  Vercel environment values were NOT inspected (Vercel CLI use was blocked; see 01).
