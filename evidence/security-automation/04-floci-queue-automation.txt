What it does (check first, create only if missing, never overwrite a mismatch)
  1. Floci container: exists? running? (start if stopped) - create only if missing and the port
     is free; verifies host port, restart policy unless-stopped, IAM enforcement, network
  2. waits for /_floci/health "sqs":"running"; AWS CLI connectivity (Floci root creds "test")
  3. queues: duplicate check; DLQ exists?; queue exists?; VisibilityTimeout, redrive target ARN
     and maxReceiveCount compared -> mismatch = FAIL + exit 3 (not overwritten); queue depths
  4. IAM: user exists?; inline policy present and semantically equal to the repo policy file
     (mismatch = exit 3, not overwritten); key file key is an ACTIVE key of that user and
     authenticates as that user (sts get-caller-identity) -> reused. No valid key file ->
     FAIL, no key created unless --allow-new-key (then max 1 key, never overwrites a file)
  5. reachability of the queue with the editorial consumer key
  Missing dependencies: docker / Docker Desktop / aws / curl / node -> exit 2 with a message.
  Modes: --verify-only (read-only), --counts, --allow-new-key, --quiet.
  Exit codes: 0 ok | 1 check failed | 2 prerequisite | 3 unexpected configuration | 4 Floci not ready

Defect: with a PAUSED Floci, "docker port" returns nothing, so the port check reported
"refusing to mix environments" (exit 3) instead of "Floci not ready" (exit 4). The refusal was
safe (workers untouched) but misclassified.
Fix in infra/floci/floci-queues.sh: (a) State.Paused -> exit 4 "paused - Floci not ready"
(never unpaused automatically); (b) the host port is read from HostConfig.PortBindings (valid
for running, paused and stopped containers). Re-verified: isolated paused -> exit 4 (T6.2 re-run),
isolated healthy --verify-only 21/21 (T6.2b), production --verify-only 21/21 within T6.7.
