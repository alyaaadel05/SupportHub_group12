REMAINING LIMITATIONS
  - Recovery from a Lambda failure relies on the platform's async retries (Floci retried once
    after 60 s; AWS retries up to 2 times). No on-failure destination / DLQ is configured; if
    every retry fails the receipt stays missing. The gap is detectable with
      SELECT ... FROM editorial_publication_event_outbox o LEFT JOIN editorial_publication_event_receipts r
      USING(event_id) WHERE o.state='published' AND r.event_id IS NULL
    but there is no automated reconciliation (requeue only handles outbox state 'failed').
  - The Lambda receives DATABASE_URL as a plain function environment variable (visible to anyone
    with lambda:GetFunctionConfiguration; denied for all component keys above). On real AWS this
    should come from Secrets Manager / KMS-encrypted env vars.
  - Floci does not verify SigV4 signatures (see 02).
