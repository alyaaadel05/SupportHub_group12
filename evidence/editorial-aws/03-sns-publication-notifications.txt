ANALYSIS OF THE 4 BASELINE FAILURES
  1-2) "payload articleId" / "payload publishedBy": TEST BUG. The values are
       correct (articleId=239, publishedBy=3; see the delivered Message above).
       The test compared the numeric payload with ids the API returns as strings.
       Fixed with Number(...) in the script; not re-run (the delivered message
       above already proves the values).
  3)   "after 5 failed attempts ... 'failed'": TEST TIMING. The 240 s poll was too
       short: each failed attempt takes ~40 s because the SDK retries the DNS
       failure "getaddrinfo EAI_AGAIN floci" before giving up, plus the 5/10/20/40 s
       backoff. The line after the Floci restart shows the real result:
       state=failed attempts=5, delivered=0 (event 35b3c114-..., article 242).
       Not repeated (long outage, ~5 min).
  4)   "an authenticated recovery path for failed SNS notifications exists": REAL DEFECT D3.

DEFECT FOUND
  D3 (FIXED) A publication notification whose automatic retries were exhausted
     stayed 'failed' forever. Nothing re-sent it: the existing protected endpoint
     /internal/retry-notifications only handles the Search outbox (verified above:
     state stayed 'failed'), and the worker only claims 'pending' rows. The event
     was persisted (not deleted) but the downstream subscriber never received it.

REMAINING LIMITATIONS
  - Requeue of 'failed' events is an operator / scheduler action (cron-secret
    endpoint); no scheduler is configured in the isolated stack (same model as
    the existing /internal/retry-notifications).
  - The worker's SNS client has no explicit request timeout; with a hung (not
    stopped) endpoint a publish could block the worker. Not tested, not changed.
  - Subscriber evidence for sections A-D comes from a verification-only SQS
    subscription (removed afterwards). Lambda delivery and receipts = Task 3 (PENDING).
  - Code changes exist only in the working tree and the isolated stack; nothing was
    deployed to Neon, Vercel, Cloudflare or production containers.
